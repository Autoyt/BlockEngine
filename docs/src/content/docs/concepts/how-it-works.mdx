---
title: How BlockEngine Works
description: The moving parts behind custom block registration, rendering, items, and creative inventory entries.
---

BlockEngine splits custom blocks into three responsibilities: registration, runtime behavior, and client presentation. That shape is similar to Paper's own documentation style: the server owns behavior, while resource packs describe what the client should display.

## Registration

Every block has a stable namespaced id:

```text
namespace:block_name
```

Code-backed blocks are registered by plugins implementing `CustomBlockSystem`. JSON-backed blocks are loaded from expansion packs at startup and converted into the same internal block definition type.

## Runtime behavior

Once registered, blocks flow through the same systems:

- placement validation
- block persistence
- break and drop handling
- optional gravity or movement behavior
- display entity management
- catalog and creative inventory exposure

Data-driven blocks use BlockEngine's default adapter. Java blocks can provide their own adapter when they need callbacks, custom state, or integration with another plugin.

## Client presentation

Minecraft clients do not know about BlockEngine block ids directly. BlockEngine bridges that gap by generating resource-pack assets:

- cube block models for each state
- item models for normal inventory items
- language strings for item and creative-menu names
- generated resource-pack zips that can be hosted and sent to players

## Creative menu entries

BlockEngine uses custom enchantment registration to make creative inventory entries appear on modern Paper servers. The startup sequence is intentionally two-step:

1. BlockEngine discovers current blocks and writes `generated-creative-enchantments.json`.
2. On the next full server restart, Paper sees that manifest during bootstrap and realizes the enchantments early enough for creative inventory generation.

The creative entry is only a placeholder. When a player takes it from the creative menu and places it into an inventory slot, BlockEngine immediately converts it into the real custom block item.

## Resource pack model routing

For creative entries, the generated resource pack follows the same pattern used by data packs: `assets/minecraft/items/enchanted_book.json` checks the `minecraft:stored_enchantments` component and routes matching BlockEngine creative enchantments to the block's custom item model.
