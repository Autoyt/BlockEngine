Data-driven packs add BlockEngine blocks with JSON and resource-pack assets. Use this path when a block can be described by configuration: textures, hardness, drops, sounds, movement flags, catalog visibility, and creative-menu visibility.

<Aside type="tip" title="When to use this path">
  Pick data-driven blocks for decorative blocks, furniture-style cubes, simple breakable/placeable blocks, or pack-driven content where writing Java would add ceremony without adding behavior.
</Aside>

## Setup

<Tabs syncKey="data-pack-setup">
  <TabItem label="Folder">

Create a folder under the BlockEngine plugin data directory:

```text
plugins/blockengine/expansion/packs/my_pack/
  pack.json
  blocks/
  assets/
  pack.png
```

Folders are easiest while iterating because you can edit JSON and texture files directly.

  </TabItem>
  <TabItem label="Zip">

Zip packs use the same internal structure:

```text
plugins/blockengine/expansion/packs/my_pack.zip
  pack.json
  blocks/
  assets/
  pack.png
```

Use zip packs when distributing a finished block pack to another server.

  </TabItem>
</Tabs>

## Feature areas

<Tabs syncKey="data-pack-features">
  <TabItem label="Pack metadata">

`pack.json` owns namespace-level settings:

<CardGrid>
  <LinkCard title="namespace" href="/BlockEngine/reference/data-driven-packs/#pack-metadata" description="Controls the block id prefix for every block in the pack." />
  <LinkCard title="title, description, prompt" href="/BlockEngine/reference/resource-packs/#sending-packs" description="Control generated resource-pack presentation and player-facing pack prompts." />
  <LinkCard title="assets" href="/BlockEngine/reference/resource-packs/#asset-and-image-constraints" description="Lists copied asset roots containing textures, models, sounds, and pack files." />
  <LinkCard title="catalog and creative-menu" href="/BlockEngine/guides/creative-inventory/" description="Define default visibility for catalog flows and vanilla creative inventory entries." />
  <LinkCard title="dependencies" href="/BlockEngine/concepts/system-lifecycle/#3-namespaces-protect-ownership" description="Require other namespaces before this pack registers." />
</CardGrid>

  </TabItem>
  <TabItem label="Block item">

The `item` object controls the inventory representation:

```json
{
  "material": "knowledge_book",
  "name": "<gold>Example Block",
  "lore": ["<gray>Placed by BlockEngine"],
  "glint": false,
  "placeable": true
}
```

MiniMessage works for the final BlockEngine item title and lore. Creative-menu enchantment titles use generated translation strings.

  </TabItem>
  <TabItem label="States">

States define how the block behaves and renders:

<CardGrid>
  <LinkCard title="Hardness and mining speed" href="/BlockEngine/code-driven/#mining-and-hardness" description="Control break timing and custom mining calculations." />
  <LinkCard title="Mining profile" href="/BlockEngine/reference/data-driven-packs/#block-file" description="Borrow vanilla mining behavior from a real Bukkit block material." />
  <LinkCard title="Preferred tools" href="/BlockEngine/code-driven/#mining-and-hardness" description="Model pickaxe, axe, shovel, hoe, shears, and sword drop behavior." />
  <LinkCard title="Drops and Silk Touch" href="/BlockEngine/reference/data-driven-packs/#block-file" description="Decide when states drop their custom item in survival or creative mode." />
  <LinkCard title="Sounds and movement" href="/BlockEngine/code-driven/#movement" description="Configure placement, break, mining, gravity, dispenser, and partial-support behavior." />
  <LinkCard title="Texture references" href="/BlockEngine/reference/resource-packs/#asset-and-image-constraints" description="Point generated block models at safe resource-pack texture paths." />
</CardGrid>

Every block must have at least one state, and `default-state` must point at a defined state.

  </TabItem>
  <TabItem label="Placement">

`placement` controls orientation behavior:

```json
{
  "placement": "directional"
}
```

Supported values are `none`, `horizontal-facing`, `axis`, and `directional`.

  </TabItem>
  <TabItem label="Creative and catalog">

`creative-menu` and `catalog` default to `true`. Disable them per pack or per block:

```json
{
  "creative-menu": false,
  "catalog": false
}
```

Creative inventory entries are discovered at runtime, written to the manifest, and realized on the next full restart.

  </TabItem>
</Tabs>

## Generated output

BlockEngine generates the model files data-pack authors normally do by hand:

```text
generated-resource-pack/data-packs/<pack>/
  assets/<namespace>/models/block/<block>/<state>.json
  assets/<namespace>/models/item/<block>.json
  assets/<namespace>/items/<block>.json
  assets/<namespace>/lang/en_us.json
```
